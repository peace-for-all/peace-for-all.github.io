Case study · Working pre-release

VoiceGuides

Listening turns a folder of long, useful guides into something that can accompany a walk—without losing the reader’s place or questions.

For
People who learn from their own text collections
Shape
Native Android app
Core constraint
Useful without internet access

The nuisance

Long Markdown guides are convenient to keep and revise, but awkward to read while walking, cooking, or doing practical work. Generic text-to-speech can read a file; it rarely treats the file as an ongoing place to think.

What became clear

The first assumption was that playback was the main problem. The awkward discovery was that continuity mattered more: resuming the right paragraph, moving by meaningful blocks, and capturing a thought without breaking attention.

Decisions

VoiceGuides uses Android’s system text-to-speech engine and system folder picker. It scans the chosen folder read-only, keeps private offline copies, remembers progress by guide, and exposes playback through the lock screen, notification, and headset controls. Markdown is parsed for listening rather than spoken as punctuation.

Notes are anchored to passages and move through explicit draft, ready, shared, and answered states. Sharing is user-initiated; opening the Android share sheet does not silently mark a question as sent.

What works now

The pre-release app plays .md, .markdown, and .txt files; resumes progress; supports voice, speed, pitch, sleep timers, offline copies, anchored notes, exploration briefs, and JSON backup and restore. It has no internet or microphone permission.

Status and limits

This is a working pre-release, not a store claim. It depends on the quality and language support of the TTS engine installed on the device. It reads source folders rather than editing them, and its backup is a file the user must deliberately save and protect.

Technology, where it matters

Kotlin, Jetpack Compose, Room, Android’s Storage Access Framework, media sessions, and system TTS support the core decisions: local ownership, background playback, and a native experience.
